1) Loot filters can silently ignore your requested slot/type

In client/src/lib/combat/loot.ts, getRandomItemFromPool() does this:
	•	filters by type/slot
	•	if empty, it falls back to the whole pool (meaning you can accidentally get the wrong thing later when you expand pools)

Fix it so it falls back safely:

Find this block:

  if (filtered.length > 0) {
    return filtered[Math.floor(Math.random() * filtered.length)];
  }

  return pool[Math.floor(Math.random() * pool.length)];

Replace with:

  if (filtered.length > 0) {
    return filtered[Math.floor(Math.random() * filtered.length)];
  }

  // Safer fallbacks (never ignore requested constraints silently)
  if (type) {
    const typeOnly = pool.filter(item => item.type === type);
    if (typeOnly.length > 0) return typeOnly[Math.floor(Math.random() * typeOnly.length)];
  }

  // If we get here, your pools are missing something you asked for
  throw new Error(`No items found for rarity=${rarity}, type=${type ?? "any"}, slot=${slot ?? "any"}`);

This prevents “weird drops” later that feel like bugs but are actually the fallback.
